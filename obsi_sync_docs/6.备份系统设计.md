# 备份系统设计

> 创建日期：2026-07-24
> 最近更新：2026-07-25

## 目标

每次执行覆盖同步前，对执行计划中即将被覆盖的从库配置项创建短期恢复快照。

备份用于同步失败或结果不符合预期时人工恢复，不承诺长期保存。恢复功能不进入第一版。

## 执行边界

备份由 `ExecuteSyncPlan(plan)` 内部强制触发，不提供绕过备份的同步入口。

应用通过 Wails `SingleInstanceOptions` 强制单实例运行。第二次启动只恢复并聚焦现有窗口，不创建新的业务进程，避免多个进程同时操作备份根目录。

执行顺序：

```text
获取同步并发锁
重新生成并确认当前同步计划
检查全部源路径和目标路径中的符号链接
检查并清理遗留临时备份目录
创建完整备份
执行同步
清理旧备份
释放同步并发锁
```

备份必须在任何同步写入前全部完成。任一配置项备份失败时：

- 删除本次未完成的临时备份目录。
- 中止整次同步。
- 将备份失败错误返回前端。

## 备份范围

只处理当前同步计划。

- `create`：目标配置项不存在，不创建备份。
- `overwrite` 文件：复制从库中的目标文件。
- `overwrite` 目录：完整复制从库中的目标目录。

目录备份保存同步前的完整状态，包括目标目录中不会被本次覆盖的额外文件。这样备份内容始终表示该配置项在同步前的快照。

如果本次计划全部为 `create`，则不创建空备份目录，`SyncResult.BackupPath` 返回空字符串。

## 符号链接策略

同步不处理任何符号链接。

同步前检查当前计划涉及的全部主库源路径和从库目标路径。发现任何符号链接，立即终止整次同步，不创建备份、不写入文件，也不跳过该链接后继续执行。

检查必须发生在备份和同步写入之前，并返回发现符号链接的具体路径。禁止跟随、读取或复制符号链接指向的内容。

## 存放位置

备份根目录：

```text
<os.UserCacheDir()>/obsi-conf-sync/backups/
```

Windows 示例：

```text
%LocalAppData%/obsi-conf-sync/backups/
```

系统缓存目录可能被操作系统、清理工具或用户删除，因此本功能只提供短期恢复能力。

## 目录结构

每次同步生成一个 `backupID`，由秒级时间和短 UUID 组成：

```go
suffix, err := shortUUID()
if err != nil {
    return errors.WithStack(err)
}
backupID := fmt.Sprintf("%s-%s",
    time.Now().Format("20060102-150405"),
    suffix,
)
```

`shortUUID()` 使用 `crypto/rand` 生成 2 字节随机值并编码为 4 位小写十六进制字符串，例如 `a83f`；随机源失败时返回错误。

示例：

```text
backups/
└── 20260724-153012-a83f/
    ├── manifest.json
    └── targets/
        ├── 001/
        │   ├── appearance.json
        │   └── themes/
        └── 002/
            └── hotkeys.json
```

同一次执行中需要备份的从库统一放入一个备份目录。只有包含 `overwrite` 项的从库才会创建目标备份目录并写入 Manifest；全部为 `create` 的从库不参与备份。

目标库使用 `001`、`002` 等编号，编号对应它在同步计划中的位置，避免同名 Vault 冲突。由于不需要备份的从库会被跳过，实际备份编号允许不连续。例如第一个从库全部为新增、第二个从库存在覆盖时，只创建 `targets/002/`。

创建过程先写入同级临时目录：

```text
.creating-20260724-153012-a83f
```

全部文件和 `manifest.json` 写入成功后，再重命名为正式备份目录。正式目录已存在时返回错误，禁止覆盖旧备份。

## 临时目录清理

创建新备份前，扫描备份根目录中的遗留临时目录：

```text
backups/.creating-*
```

清理规则：

1. 只枚举备份根目录的直属子目录，不递归扫描其他位置。
2. 只处理符合 `.creating-<yyyyMMdd-HHmmss>-<4位小写十六进制>` 命名的普通目录。
3. 符号链接、名称不符合规则的目录和普通文件不处理。
4. 删除前确认目录解析后的绝对路径仍位于备份根目录内。
5. 任一遗留临时目录清理失败时，中止本次备份和同步并返回错误。
6. 清理完成后再创建本次 `.creating-<backupID>` 临时目录。

## Manifest

`manifest.json` 记录备份与原 Vault 的对应关系：

```go
type BackupManifest struct {
    CreatedAt     string         `json:"createdAt"`
    MainVaultPath string         `json:"mainVaultPath"`
    Targets       []BackupTarget `json:"targets"`
}

type BackupTarget struct {
    ID        string       `json:"id"`
    VaultPath string       `json:"vaultPath"`
    Items     []BackupItem `json:"items"`
}

type BackupItem struct {
    Path   string         `json:"path"`
    Action SyncPlanAction `json:"action"`
}
```

- `CreatedAt` 使用带时区和小数秒的 RFC 3339 Nano 时间，作为同一秒内多个备份的排序依据。
- `ID` 对应 `targets/<ID>/`。
- `Targets` 只记录实际完成覆盖项备份的从库；同步计划中全部为 `create` 的从库不会写入 Manifest。
- `Items` 只记录实际完成备份的 `overwrite` 项。
- `Path` 保持相对 `.obsidian` 的同步路径。

Manifest 与备份文件共同成功后，本次备份才视为完整备份。

有效 Manifest 必须满足：

- `manifest.json` 是普通文件且不是符号链接。
- JSON 可以解析，`CreatedAt` 是有效的 RFC 3339 Nano 时间。
- `MainVaultPath` 非空，`Targets` 非空且 ID 唯一。
- 每个目标 ID 符合三位及以上数字格式，对应的目标备份目录存在且不是符号链接。
- 每个 Manifest Target 至少包含一个实际完成备份的 `overwrite` 项。
- 每个配置项路径是合法相对路径，对应备份文件或目录存在且不是符号链接。

## 保留策略

备份根目录全局只保留最新 10 个完整备份，不按 Vault 分组计数。

每次同步结束后：

1. 只枚举备份根目录的直属子目录。
2. 只识别符合 `<yyyyMMdd-HHmmss>-<4位小写十六进制>` 命名且包含有效 `manifest.json` 的普通目录。
3. 按 Manifest 的 `CreatedAt` 从新到旧排序。
4. 尝试删除第 11 个及更早的完整备份。

临时目录、名称不符合规则的目录、符号链接和缺少有效 Manifest 的目录不参与完整备份计数，也不由旧备份保留策略删除。

旧备份清理失败不改变同步结果，通过应用日志记录警告，等待下次执行再次清理；因此清理失败时允许完整备份暂时超过 10 个。

## 返回结果

`SyncResult` 增加本次备份目录：

```go
type SyncResult struct {
    BackupPath string             `json:"backupPath"`
    Targets    []TargetSyncResult `json:"targets"`
}
```

- 存在覆盖项且备份成功时，返回正式备份目录绝对路径。
- 全部为新增项时返回空字符串。
- 备份失败时不执行同步，直接返回错误。

结果页在 `BackupPath` 非空时显示“打开备份目录”按钮。

后端提供打开接口，并校验传入目录位于当前应用备份根目录内：

```go
OpenSyncBackupDir(backupPath string) error
```

安全检查不能只依赖未经错误处理的字符串前缀比较。接口必须依次执行：

1. 使用 `filepath.Abs` 和 `filepath.Clean` 解析备份根目录与输入路径，并处理错误。
2. 使用 `filepath.Rel(root, target)` 判断路径关系。
3. 输入路径必须是备份根目录的直属子目录；禁止根目录自身、嵌套子目录和 `..` 逃逸路径。
4. 目录名必须符合 `<yyyyMMdd-HHmmss>-<4位小写十六进制>`。
5. 使用 `os.Lstat` 确认目标是普通目录且不是符号链接。
6. 目录内必须存在有效的普通文件 `manifest.json`；Manifest 不能是符号链接。
7. 全部检查通过后才能调用系统文件管理器打开目录。

核心路径关系检查：

```go
root, err := filepath.Abs(backupRoot)
if err != nil {
    return errors.WithStack(err)
}
root = filepath.Clean(root)

target, err := filepath.Abs(input)
if err != nil {
    return errors.WithStack(err)
}
target = filepath.Clean(target)

rel, err := filepath.Rel(root, target)
if err != nil {
    return errors.WithStack(err)
}
if rel == "." ||
    rel == ".." ||
    strings.HasPrefix(rel, ".."+string(os.PathSeparator)) ||
    filepath.Dir(rel) != "." {
    return errors.New("无效的备份目录")
}
```

不能直接使用下面的检查作为完整安全边界：

```go
strings.HasPrefix(target, root+string(os.PathSeparator))
```

它不能限制目标必须是根目录的直属备份目录，也不能替代目录命名、符号链接和 Manifest 校验。

## 第一版不包含

- 自动恢复或一键回滚。
- 用户配置备份目录。
- 用户配置保留数量。
- 长期归档保证。
- 压缩、加密或云端备份。
- 三秒调用间隔限制。

## 验收标准

- 每次存在覆盖项的同步都会先创建备份。
- 备份仅来自执行计划中的从库覆盖项。
- 同步前检查全部主库源路径和从库目标路径中的符号链接。
- 发现任何符号链接时会中止整次同步，不创建备份、不写入文件，也不继续处理其他同步项。
- 检查和执行过程不会跟随、读取或复制符号链接指向的内容。
- 多个从库可以在同一次备份中正确区分。
- 任一备份失败时没有同步写入。
- 同步部分失败时仍保留同步前备份。
- 全部为新增项时不产生空备份目录。
- 创建备份前会清理符合规则的遗留 `.creating-*` 临时目录。
- 临时目录清理失败时不会执行同步。
- 每次同步后尝试将完整备份清理至最新 10 个，清理失败时允许暂时超过 10 个。
- 旧备份保留策略不处理非备份目录、临时目录或符号链接。
- `SyncResult.BackupPath` 与实际备份目录一致。
- 打开目录接口只接受备份根目录下直属、完整且非符号链接的备份目录。
- 前端可以打开本次备份目录。
